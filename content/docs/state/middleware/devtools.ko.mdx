# DevTools

`devtools` 미들웨어는 `@ilokesto/state` 스토어를 Redux DevTools 확장 프로그램에 연결합니다. 상태 변경이 DevTools 타임라인에 표시되므로 스냅샷을 확인하고, 히스토리를 다시 재생하고, Redux 도구로 스토어 로직을 디버깅할 수 있습니다.

## 사용법

`devtools`는 스토어에 직접 적용하거나 미들웨어 팩토리에 포함할 수 있습니다.

```ts lineNumbers
import { devtools } from '@ilokesto/state/middleware';

const store = devtools('CounterStore')({ count: 0 });
```

## 연결 및 초기화 흐름 (Connect and Init Flow)

`devtools`가 시작되면 다음 순서로 동작합니다.
1. **확장 프로그램 확인**: `window.__REDUX_DEVTOOLS_EXTENSION__`을 읽고, 확장 프로그램이 없으면 설정을 건너뜁니다.
2. **연결 (Connect)**: 제공된 스토어 이름으로 DevTools 연결을 엽니다.
3. **초기화 (Init)**: 현재 스토어 상태를 초기 스냅샷으로 전송합니다.
4. **운영 환경 가드**: 운영 빌드에서는 아무 동작도 하지 않는 래퍼를 반환합니다.

## 액션 라벨 및 이름 (Action Labels and Names)

DevTools 업데이트는 `${storeName}:${actionName}` 라벨 형식을 사용합니다.

### 1. 일반 상태 업데이트 (Plain State Updates)
일반 `setState` 호출은 기본 이름인 `anonymous action`을 사용합니다.

```ts lineNumbers
// 라벨: CounterStore:anonymous action
setState({ count: 10 });
```

### 2. 리듀서 디스패치 (Reducer Dispatch)
리듀서 스토어는 디스패치된 액션 타입을 액션 이름으로 전송합니다.

```ts lineNumbers
// 라벨: CounterStore:increment
dispatch({ type: 'increment' });
```

### 3. 내부 스탬핑 (Internal Stamping)
리듀서 모드에서는 dispatch 중에 `store.actionName`이 잠시 기록되고, `devtools`는 그 값을 outgoing label로 읽습니다. 일반 상태 모드에는 같은 이름 지정 경로가 없으므로, 애플리케이션 코드가 자체 라벨을 추가하지 않는 한 업데이트는 anonymous action으로 남습니다.

## 인바운드 명령 처리 (Inbound Commands)

미들웨어는 DevTools 확장 프로그램에서 오는 다음 명령을 처리합니다.

- **`RESET`**: 스토어를 원래의 초기 상태로 되돌립니다.
- **`COMMIT`**: 현재 상태를 새로운 초기 베이스로 만듭니다.
- **`ROLLBACK`**: 마지막 커밋 이후의 모든 액션을 버리고 해당 상태로 돌아갑니다.

## 리듀서와의 상호작용 (Reducer Interplay)

리듀서 스토어는 각 outgoing message에 reducer action type을 담을 수 있으므로 DevTools 히스토리가 더 명확해집니다.

## 디버깅 가이드

- **각 스토어에 이름 지정**: `devtools()`에 고유한 이름을 전달하십시오. `AuthStore`나 `CartStore`처럼 명확한 이름은 여러 스토어의 DevTools 히스토리를 읽기 쉽게 만듭니다.
- **운영 코드 유지**: 운영 빌드를 위해 `devtools()`를 수동으로 제거할 필요가 없습니다. 미들웨어가 환경을 감지하고 아무 동작도 하지 않는 래퍼를 반환합니다.
- **액션 세부 정보 개선**: `anonymous action` 라벨이 너무 많이 보인다면 더 많은 로직을 명명된 액션으로 옮기거나 리듀서 모드를 사용해 히스토리를 더 명확하게 만드십시오.
