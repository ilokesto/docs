# Utilities

`@ilokesto/state/utils` contains small helpers for cases where the base `create()` API is already right, but the setup code needs a clearer shape.

The two helpers solve different problems:

- `pipe` composes store creation with middleware. Start with plain initial state, apply middleware from left to right, then pass the returned `Store` to `create(store)`.
- `adaptor` wraps Immer's `produce()`. Write a draft-style object update, then pass the returned updater to `writeOnly()` or another store write path.

## Choosing between them

Use `pipe` when store setup is the noisy part.

Use `adaptor` when object update syntax is the noisy part.

Stay with plain `create()` when you do not need middleware composition or draft-style object updates.

| Your code feels noisy because... | Use |
|---|---|
| Several middleware need a readable order | [`pipe`](./pipe) |
| Nested object writes require too much spreading | [`adaptor`](./adaptor) |
| The store is already clear with one initial object | plain [`create`](../create) |

## How they differ

`pipe` works before adapter binding. It builds the store instance that `create(store)` will bind.

`adaptor` works during writes. It turns an Immer draft recipe into a pure updater function for object state.

## How they fit together

The helpers can appear in the same feature, but at different moments.

```ts lineNumbers
import { create } from '@ilokesto/state/react';
import { persist } from '@ilokesto/state/middleware';
import { adaptor, pipe } from '@ilokesto/state/utils';

const useProfile = create(
  pipe(
    { profile: { name: 'Ari' } },
    persist({ local: 'profile' })
  )
);

export const renameProfile = (name: string) => {
  useProfile.writeOnly()(adaptor((draft) => {
    draft.profile.name = name;
  }));
};
```

`pipe` shapes the store before a framework adapter binds to it. `adaptor` shapes one write after the store exists.
