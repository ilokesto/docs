# 영속화

`persist`는 스토어 상태를 브라우저 저장소에 저장하고, 스토어가 다시 시작될 때 복원합니다. 메모리 안의 스토어와 선택한 저장소 대상을 같은 상태로 유지합니다.

## 사용법

`persist`를 스토어 객체에 적용하거나, 스토어를 만들 때 커링된 미들웨어 팩토리로 사용합니다.

```ts lineNumbers
import { persist } from '@ilokesto/state/middleware';

const store = persist({ local: 'counter-storage' })({ count: 0 });
```

## 저장소 구성

설정 객체는 세 가지 저장소 대상을 받습니다.

- **`local`**: (string) `localStorage`에 저장할 키 이름입니다. 브라우저를 다시 열어도 남아야 하는 데이터에 사용합니다.
- **`session`**: (string) `sessionStorage`에 저장할 키 이름입니다. 탭이 닫힐 때 사라져야 하는 데이터에 사용합니다.
- **`cookie`**: (string) 쿠키 저장소에 저장할 키 이름입니다. 서버가 읽어야 할 수 있는 작은 상태 조각에 사용합니다.

## 복원 흐름

`persist`로 초기화된 스토어는 일반 사용 전에 저장된 상태를 복원합니다.
1. **초기 상태**: 스토어는 제공된 초기 상태로 시작합니다.
2. **동기 읽기**: 미들웨어는 설정된 저장소 대상에서 영속화된 상태를 즉시 읽습니다.
3. **교체**: 저장된 데이터가 유효하면 복원된 상태가 현재 스토어 상태가 됩니다.
4. **참조 변경 가드**: 복원된 상태가 초기 상태와 다를 때만 스토어 참조가 바뀝니다.

## 저장소 형태 및 버전 관리

영속화된 데이터는 래퍼 객체에 저장됩니다.
```json lineNumbers
{
  "state": { ... },
  "version": 2
}
```

- **버전 계산**: 현재 `version`은 `migrate` 체인의 길이에서 나옵니다. 마이그레이션 함수가 세 개라면 버전은 `3`입니다.
- **Write-through 동작**: 스토어 커밋이 발생할 때마다 미들웨어는 새 상태를 저장소에 씁니다.
- **쓰기 캐시**: 미들웨어는 인코딩된 영속화 payload를 캐시하고, 다음 인코딩 값이 같으면 저장소 쓰기를 건너뜁니다.

## 마이그레이션

`migrate` 옵션은 오래된 상태 형태를 현재 형태로 바꾸는 함수 배열을 받습니다.

- **대상 제약**: 마이그레이션은 `local` 및 `cookie` 대상에서 지원됩니다. `session` 저장소는 마이그레이션을 지원하지 않습니다.
- **점진적 업데이트**: 배열의 각 함수는 하나의 버전 단계를 나타냅니다. 저장된 버전이 `1`이고 현재 체인 길이가 `3`이면 함수 `[1]`과 `[2]`가 차례로 실행됩니다.

## 쿠키 제약 사항

`cookie` 대상에는 브라우저 제한이 있습니다.
- **크기**: 쿠키는 보통 4KB로 제한됩니다. 큰 상태 트리는 영속화에 실패합니다.
- **직렬화**: 데이터는 JSON으로 직렬화됩니다. 상태에 순환 참조나 함수, 클래스 같은 직렬화할 수 없는 객체를 넣지 마세요.

## 미들웨어 순서

미들웨어 체인 안에서 `persist()`의 위치는 저장되는 상태를 바꿉니다.

**권장 순서**: `persist()`를 체인의 끝에 가깝게 배치합니다.
그러면 `validate`나 `debounce` 같은 미들웨어가 먼저 업데이트를 처리하고, `persist`는 최종 상태를 저장합니다.

```ts lineNumbers
const store = pipe(
  validate(schema),
  persist({ local: 'app-state' })
)({ count: 0 });
```
