# DevTools

The `devtools` middleware connects an `@ilokesto/state` store to the Redux DevTools extension. State changes appear in the DevTools timeline, so you can inspect snapshots, replay history, and debug store logic with familiar Redux tooling.

## Usage

Apply `devtools` directly to a store, or include it in a middleware factory.

```ts lineNumbers
import { devtools } from '@ilokesto/state/middleware';

const store = devtools('CounterStore')({ count: 0 });
```

## Connect and Init Flow

When `devtools` starts:
1. **Extension check**: Reads `window.__REDUX_DEVTOOLS_EXTENSION__` and skips setup when the extension is missing.
2. **Connect**: Opens a DevTools connection with the provided store name.
3. **Init**: Sends the current store state as the initial snapshot.
4. **Production guard**: Returns a no op wrapper in production builds.

## Action Labels and Names

DevTools updates use the `${storeName}:${actionName}` label format.

### 1. Plain State Updates
Plain `setState` calls use the default `anonymous action` name.

```ts lineNumbers
// Label: CounterStore:anonymous action
setState({ count: 10 });
```

### 2. Reducer Dispatch
Reducer stores send the dispatched action type as the action name.

```ts lineNumbers
// Label: CounterStore:increment
dispatch({ type: 'increment' });
```

### 3. Internal Stamping
In reducer mode, dispatch temporarily writes `store.actionName`, and `devtools` reads that value for the outgoing label. Plain state mode has no matching naming path, so those updates stay anonymous unless application code adds its own labels.

## Inbound Commands

The middleware handles these commands from the DevTools extension:

- **`RESET`**: Reverts the store to its original initial state.
- **`COMMIT`**: Takes the current state and makes it the new initial base.
- **`ROLLBACK`**: Discards all actions after the last commit and returns to that state.

## Reducer Interplay

Reducer stores produce clearer DevTools history because each outgoing message can carry the reducer action type.

## Debugging Guidance

- **Name each store**: Pass a unique name to `devtools()`. Clear names such as `AuthStore` or `CartStore` keep multi store DevTools history readable.
- **Keep production code simple**: Leave `devtools()` in place for production builds. The middleware detects the environment and returns a no op wrapper.
- **Improve action detail**: If too many `anonymous action` labels appear, move more logic into named actions or use reducer mode for clearer history.
