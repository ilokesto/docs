# 핵심 개념

`@ilokesto/store`는 하나의 동기적 값 컨테이너라고 생각하면 가장 이해하기 쉽습니다. 상태 값을 보관하고, 그 값을 교체하며, 성공한 교체 뒤에 리스너에게 알립니다.

## 계약으로서의 Store

`Store<T>`는 하나의 상태 원자에 대한 계약입니다. 공개 계약은 작습니다. 스토어를 만들고, 현재 값이나 초기 값을 읽고, 값을 교체하고, 미들웨어를 추가하고, 변경 알림을 구독합니다.

이 계약에는 프레임워크 렌더링, selector, reducer, persistence, data fetching, devtools, 비동기 batching이 포함되지 않습니다. 그런 기능은 스토어 주변에 만들 수 있지만, 패키지 자체의 일부는 아닙니다.

## 상태 스냅샷

`getState()`는 현재 상태 참조를 반환합니다. `getInitialState()`는 생성자에 전달했던 값을 반환합니다.

두 메서드는 모두 `Readonly<T>` 타입입니다. 이는 값을 스냅샷으로 다루라는 TypeScript 신호입니다. 소스는 런타임에 상태를 동결, 복제, 프록시 처리하지 않습니다.

```ts lineNumbers
const store = new Store({ count: 0 });

const current = store.getState();
const initial = store.getInitialState();
```

## 읽기

읽기는 직접적이고 동기적입니다. 파생 읽기 시스템이나 속성 수준 추적은 없습니다.

컨슈머에게 파생 값이 필요하다면 스토어 밖에서 계산하거나 더 높은 수준의 어댑터에서 계산하세요.

```ts lineNumbers
const count = store.getState().count;
const isEmpty = count === 0;
```

## 업데이트

`setState`는 다음 값 또는 업데이트 함수를 받습니다.

```ts lineNumbers
store.setState({ count: 1 });

store.setState((prev) => ({
  ...prev,
  count: prev.count + 1,
}));
```

다음 상태가 이전 상태에 의존할 때는 업데이트 함수 형태를 사용하세요.

## 교체 시맨틱

업데이트는 전체 상태 값을 교체합니다. 객체 상태는 병합되지 않습니다.

```ts lineNumbers
const store = new Store({ a: 1, b: 2 });

store.setState({ a: 10 });
// Current state is { a: 10 }. The b field was not preserved.
```

필드를 유지하려면 직접 보존하세요.

```ts lineNumbers
store.setState((prev) => ({ ...prev, a: 10 }));
```

## 구독 생명주기

`subscribe`는 리스너를 등록하고 구독 취소 함수를 반환합니다.

```ts lineNumbers
const unsubscribe = store.subscribe(() => {
  console.log(store.getState());
});

unsubscribe();
```

리스너는 성공한 교체 뒤에 동기적으로 실행됩니다. 알림에는 리스너 집합의 스냅샷을 사용하므로, 알림 도중 리스너를 제거해도 현재 순회 중인 배열은 바뀌지 않습니다.

Store는 리스너 참조를 `Set`에 보관합니다. 같은 함수 참조를 여러 번 등록해도 한 번만 저장됩니다.

## 동등성과 베일아웃 동작

상태를 교체하기 전에 Store는 이전 값과 해결된 다음 값을 `Object.is`로 비교합니다.

`Object.is(prevState, nextState)`가 `true`이면 Store는 상태를 교체하지 않고 리스너에게 알리지 않은 채 반환합니다.

```ts lineNumbers
store.setState((prev) => {
  if (prev.count >= 10) return prev;

  return { ...prev, count: prev.count + 1 };
});
```

객체와 배열에서는 새 참조가 변경을 표현하는 일반적인 방법입니다.

## Mutation 주의사항

`getState()`가 반환한 값을 mutate하지 마세요.

```ts lineNumbers
const state = store.getState();

state.items.push("new item");
```

이 직접 mutation은 `setState`를 호출하지 않으므로 리스너에게 알리지 않습니다. 같은 객체 참조가 이미 바뀐 상태라 이후 `Object.is` 확인도 추론하기 어려워질 수 있습니다.

대신 불변 교체를 사용하세요.

```ts lineNumbers
store.setState((prev) => ({
  ...prev,
  items: [...prev.items, "new item"],
}));
```

## 프레임워크 어댑터와의 관계

프레임워크 어댑터는 Store를 상태와 구독 프리미티브로 다뤄야 합니다. 렌더링, 생명주기 정리, selector, 스케줄링, 메모이제이션 규칙 같은 프레임워크별 관심사는 어댑터가 소유합니다.

이 분리는 `@ilokesto/store`를 plain TypeScript에서 쓸 수 있게 유지하면서도 프레임워크 패키지가 안정적인 기반 위에 올라설 수 있게 합니다.
