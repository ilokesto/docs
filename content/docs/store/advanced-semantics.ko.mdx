# 고급 시맨틱

이 페이지는 `Store<T>` 위에 진지한 상태 흐름이나 어댑터를 만들 때 중요한 `@ilokesto/store`의 정확한 동작을 모았습니다.

메서드 시그니처는 [API Reference](./api)에서 먼저 확인하십시오. 입문 개념은 [Core Concepts](./core-concepts)를 읽으십시오. 어댑터 경계는 [Building on Store](./building-on-store)를 참고하십시오.

## 공개 계약 경계

공개 계약은 문서화된 `Store<T>` 메서드에서 컨슈머가 의존할 수 있는 동작입니다. 상태 읽기, 상태 설정, 변경 구독이 여기에 해당합니다.

아래 일부 섹션은 관찰 가능한 동작을 설명하기 위해 현재 구현 세부 사항을 언급합니다. 이런 설명은 구현 노트로 다루고, private 필드나 정확한 내부 코드 형태가 유지된다는 약속으로 받아들이지 마십시오.

## 업데이트 교체와 순서

`setState`는 전체 상태 값을 교체합니다. 객체를 병합하지 않습니다.

```ts lineNumbers
const store = new Store({ a: 1, b: 2 });

store.setState({ a: 10 });
// 현재 상태: { a: 10 }
```

다음 값이 이전 값에 의존한다면 업데이트 함수 형태를 사용하십시오. 그래야 `setState`가 실행되는 순간의 현재 상태를 기준으로 업데이트됩니다.

```ts lineNumbers
store.setState((prev) => ({ ...prev, b: prev.b + 1 }));
```

순서는 동기식입니다. 하나의 `setState` 호출은 다음 사용자 코드 줄로 넘어가기 전에 자신의 업데이트 흐름을 끝냅니다. `setState`를 연달아 두 번 호출하면, 두 번째 호출은 첫 번째 성공 호출이 만든 상태를 봅니다.

## 동등성 베일아웃

스토어는 다음 값을 해석한 뒤 `Object.is(prevState, nextState)`를 사용합니다. `Object.is`가 `true`를 반환하면 상태를 교체하지 않고 구독자에게 알림도 보내지 않습니다.

```ts lineNumbers
store.setState((prev) => prev);
// 교체 없음, 알림 없음.
```

객체와 배열에서는 같은 참조를 반환하는 것이 베일아웃입니다. 변경을 발행하려면 새 참조를 만드십시오.

## 중첩 객체 시맨틱

중첩 값은 추적되지 않습니다. 스토어는 루트 상태 값만 `Object.is`로 비교합니다.

```ts lineNumbers
const state = store.getState();

state.profile.name = "Ada";
// 객체를 직접 수정합니다. setState를 호출하지 않으므로 구독자에게 알림이 가지 않습니다.
```

중첩 데이터에는 불변 업데이트를 사용하십시오.

```ts lineNumbers
store.setState((prev) => ({
  ...prev,
  profile: {
    ...prev.profile,
    name: "Ada",
  },
}));
```

`Readonly<T>`는 TypeScript 신호일 뿐입니다. 현재 소스는 런타임에 상태를 동결, 복제, 프록시 처리하지 않습니다.

## 알림 타이밍

알림은 동기식입니다. 성공적으로 교체된 뒤 구독자는 같은 `setState` 호출 흐름 안에서 즉시 실행됩니다.

구독자는 방금 적용된 상태를 읽습니다.

```ts lineNumbers
store.subscribe(() => {
  console.log(store.getState());
});

store.setState({ count: 1 });
// 이 호출이 반환되기 전에 구독자가 실행됩니다.
```

`@ilokesto/store` 내부에는 문서화된 batching, async scheduling, timer, promise boundary, framework render queue가 없습니다.

## 구독자 순서

구독자는 리스너 함수로 저장됩니다. 현재 구현은 리스너를 `Set`에 보관하고 알림 전에 스냅샷 배열을 만듭니다.

관찰 가능한 결과는 이렇습니다. 해당 알림의 스냅샷에 있는 리스너는 구독이 추가된 순서대로 실행됩니다.

같은 함수 참조를 두 번 이상 등록해도 여러 항목이 생기지 않습니다. `Set`은 고유한 참조를 한 번만 저장하기 때문입니다.

## 알림 중 구독 취소

알림 중에 unsubscribe 함수를 호출해도 안전합니다.

```ts lineNumbers
const unsubscribe = store.subscribe(() => {
  unsubscribe();
});
```

현재 구현은 순회 전에 `Array.from(this.listeners)`로 리스너를 스냅샷합니다. 따라서 알림 중 리스너를 제거해도 진행 중인 알림 스냅샷은 바뀌지 않습니다.

이는 현재 동작 설명입니다. 공개 어댑터를 작성할 때 private 필드 이름이나 정확한 스냅샷 구현에 의존하지 마십시오.

## 재진입 업데이트

구독자는 알림이 실행되는 동안 `setState`를 호출할 수 있습니다. 그러면 또 다른 동기식 업데이트 흐름이 즉시 시작됩니다.

```ts lineNumbers
store.subscribe(() => {
  const { count } = store.getState();

  if (count < 3) {
    store.setState({ count: count + 1 });
  }
});
```

이 패턴을 사용할 때는 guard를 두십시오. 결국 멈추는 조건이 없으면 재진입 업데이트가 무한 루프를 만들 수 있습니다.

## 오류 동작

구독자 오류는 스토어 계약에서 잡아주지 않습니다. 구독자가 throw하면 그 오류는 현재 `setState` 호출 밖으로 전파된다고 예상하십시오.

구독자는 작고 예측 가능하게 유지하십시오. 실패가 호출자를 중단하면 안 되는 경우에는 직접 오류 처리를 추가하십시오.

## 함수 값을 루트 상태로 둘 때

`setState`는 함수 인자를 업데이트 함수로 처리합니다. 함수 루트 값은 이전 상태와 함께 호출되므로 `setState`로 직접 설정할 수 없습니다.

함수를 저장해야 한다면 객체로 감싸십시오.

```ts lineNumbers
store.setState({ handler: () => console.log("run") });
```

## 구현 노트

다음 사실은 현재 구현을 설명합니다. 디버깅에는 유용하지만 애플리케이션 코드의 의존성이 되어서는 안 됩니다.

- 상태 적용은 값 또는 업데이트 함수 결과를 해석하고, `Object.is`를 확인하고, 상태를 교체한 뒤 알림을 보냅니다.
- 리스너 알림은 현재 `Array.from(this.listeners)`로 스냅샷합니다.
- `Readonly<T>`는 타입 전용입니다. 현재 소스는 상태 값을 동결, 복제, 프록시 처리하지 않습니다.
- 현재 소스에는 소스 기반 메서드를 통한 미들웨어 지원이 있지만, 이 페이지는 미들웨어를 Store의 주 계약으로 정의하지 않습니다. 공개 예제에서 미들웨어를 사용하기 전에는 문서화된 공개 메서드를 [API Reference](./api)에서 확인하십시오.

## 요약

- 업데이트는 루트 상태 값을 교체합니다.
- `Object.is`가 베일아웃 동작을 결정합니다.
- 알림은 성공적인 교체 뒤 동기적으로 전달됩니다.
- 중첩 mutation은 새 루트 참조로 `setState`를 호출하지 않는 한 보이지 않습니다.
- 리스너 스냅샷 덕분에 현재 구현에서는 알림 중 구독 해제가 안전합니다.
- 공개 문서는 관찰 가능한 동작을 설명하며 private 구현 안정성을 보장하지 않습니다.
