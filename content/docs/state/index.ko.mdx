# @ilokesto/state

`@ilokesto/state`는 외부 스토어 상태를 프레임워크별 어댑터로 바꿉니다. 패키지 root는 패키지 경계일 뿐이고, 실제 API는 `@ilokesto/state/react`, `@ilokesto/state/vue`, `@ilokesto/state/svelte` 같은 framework subpath 아래에 있습니다.

## 이 패키지가 제공하는 것

- React, Vue, Angular, Svelte, Solid를 위한 framework adapter
- 상태 객체, vanilla store, reducer를 받는 어댑터별 `create()` 모양
- 프레임워크 읽기 범위를 좁히는 selector 구독
- 프레임워크 생명주기 밖 작업을 위한 `writeOnly()` 같은 명령형 접근자
- 로깅, 영속화, 검증, 디버깅을 위한 스토어 미들웨어

## 의도적으로 제공하지 않는 것

- Provider 중심 앱 구조
- Zustand 스타일 initializer
- 셀렉터용 custom equality API
- root-level `create` export. framework subpath를 선택해야 합니다.

## 설치

```package-install
@ilokesto/state
```

## 훑어보기

```tsx lineNumbers
import { create } from '@ilokesto/state/react';

const useCounter = create({ count: 0 });

function Counter() {
  const [count, setState] = useCounter((state) => state.count);

  return (
    <button onClick={() => setState((prev) => ({ ...prev, count: prev.count + 1 }))}>
      {count}
    </button>
  );
}
```

모양은 작습니다.

- `create()`가 외부 상태를 framework adapter로 바꾸고,
- selector가 framework subscriber가 읽을 범위를 정하고,
- writer는 여전히 전체 store state를 갱신합니다.

## 어디에 쓰면 좋을까

상태가 한 컴포넌트에만 속한다면 framework-local state로 충분합니다. 여러 컴포넌트가 theme 객체나 service처럼 안정적인 의존성을 공유해야 한다면 context/provider가 잘 맞습니다. 여러 컴포넌트가 같은 변화하는 값을 구독해야 하고, 그 상태를 framework runtime 바깥에 두고 싶다면 `@ilokesto/state`를 사용하세요.

framework 바깥에 있다는 점이 핵심입니다. 액션, 미들웨어, 테스트, non-framework 코드가 같은 상태 컨테이너와 대화할 수 있고, 각 UI 계층은 자기 framework에 맞는 adapter 모양만 사용합니다.
