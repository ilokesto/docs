# Framework Usage

`@ilokesto/store` does not ship official React, Vue, Svelte, or Angular packages. The examples below are small adapter patterns around the vanilla `Store` API: `getState()`, `setState(next)`, and `subscribe(listener)`.

Use these examples when you want a copy-paste-ready starting point, then keep any selectors, actions, or framework-specific ergonomics in your own layer.

## Adapter model

Every framework bridge follows the same flow:

1. Read the current snapshot with `store.getState()`.
2. Subscribe with `store.subscribe(listener)`.
3. Mirror the latest snapshot into the framework runtime.
4. Forward writes through `store.setState(next)` or through action helpers.
5. Run cleanup by calling the returned unsubscribe function when the owning scope ends.

Keep the vanilla store as the source of truth. The adapter should translate snapshots into the framework model, not mutate the snapshot in place or depend on private fields.

## React

React has a built-in bridge for external stores: `useSyncExternalStore`. Use it so React controls subscription cleanup and reads a consistent snapshot during render.

```tsx
import { useSyncExternalStore } from "react";
import { Store } from "@ilokesto/store";

type CounterState = {
  count: number;
};

export const counterStore = new Store<CounterState>({ count: 0 });

export function useCounterStore() {
  return useSyncExternalStore(
    counterStore.subscribe.bind(counterStore),
    () => counterStore.getState(),
    () => counterStore.getInitialState(),
  );
}

export function incrementCounter() {
  counterStore.setState((state) => ({ count: state.count + 1 }));
}

export function CounterButton() {
  const state = useCounterStore();

  return <button onClick={incrementCounter}>Count: {state.count}</button>;
}
```

The hook does not add selectors or batching. It only connects `subscribe` and `getState` to React's external-store contract, while `getInitialState()` gives SSR and hydration a stable, deterministic server snapshot.

## Vue

In Vue, mirror the store snapshot into a `shallowRef` and register lifecycle cleanup with `onUnmounted`.

```ts
import { onUnmounted, shallowRef } from "vue";
import { Store } from "@ilokesto/store";

type CounterState = {
  count: number;
};

export const counterStore = new Store<CounterState>({ count: 0 });

export function useCounterStore() {
  const state = shallowRef(counterStore.getState());

  const unsubscribe = counterStore.subscribe(() => {
    state.value = counterStore.getState();
  });

  onUnmounted(unsubscribe);

  function increment() {
    counterStore.setState((current) => ({ count: current.count + 1 }));
  }

  return { state, increment };
}
```

Use `shallowRef` when the store replaces whole snapshots. Avoid mutating `state.value` directly, because `Readonly<T>` is only a TypeScript signal and the core store does not freeze values at runtime.

## Svelte

Svelte's store contract is also subscription based. A small adapter can expose a readable store for snapshots and separate action helpers for writes.

```ts
import { readable } from "svelte/store";
import { Store } from "@ilokesto/store";

type CounterState = {
  count: number;
};

export const counterStore = new Store<CounterState>({ count: 0 });

export const counter = readable(counterStore.getState(), (set) => {
  set(counterStore.getState());

  const unsubscribe = counterStore.subscribe(() => {
    set(counterStore.getState());
  });

  return unsubscribe;
});

export function incrementCounter() {
  counterStore.setState((state) => ({ count: state.count + 1 }));
}
```

Returning `unsubscribe` from the readable setup function gives Svelte the cleanup function it needs when the last subscriber leaves.

## Angular

Angular can bridge the store into a service-owned signal. The service owns the subscription, exposes a read model for components, and provides an explicit cleanup method for the scope that creates it.

```ts
import { Injectable, OnDestroy, signal } from "@angular/core";
import { Store } from "@ilokesto/store";

type CounterState = {
  count: number;
};

@Injectable()
export class CounterStoreService implements OnDestroy {
  private readonly store = new Store<CounterState>({ count: 0 });
  readonly state = signal(this.store.getState());

  private readonly unsubscribe = this.store.subscribe(() => {
    this.state.set(this.store.getState());
  });

  increment() {
    this.store.setState((state) => ({ count: state.count + 1 }));
  }

  ngOnDestroy() {
    this.unsubscribe();
  }
}
```

Provide the service at the component or feature scope when you need cleanup tied to that scope. If it is provided at the application root, the subscription usually lives for the app lifetime.

## Caveats for every adapter

- **Snapshot consistency**: Read snapshots through `getState()` inside the framework's expected subscription model. React should use `useSyncExternalStore` for this bridge.
- **Cleanup**: Always call the unsubscribe function, or return it to the framework API that owns teardown.
- **Mutation avoidance**: Treat snapshots as immutable values. `Readonly<T>` does not freeze or clone state at runtime.
- **No scheduler assumptions**: Store notifications are synchronous. The package does not add framework batching, async scheduling, or render coordination.
- **Adapter scope**: These examples are adapter patterns, not official framework packages. Keep framework-specific selectors and actions above the raw store bridge.
