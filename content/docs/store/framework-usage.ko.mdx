# 프레임워크 사용법

`@ilokesto/store`는 공식 React, Vue, Svelte, Angular 패키지를 제공하지 않습니다. 바닐라 `Store` API인 `getState()`, `setState(next)`, `subscribe(listener)` 위에 작은 어댑터를 얹어 사용하세요.

selector, action, 프레임워크별 helper는 각자의 계층에 두세요.

## 어댑터 모델

모든 어댑터는 같은 흐름을 따릅니다.

1. `store.getState()`로 현재 스냅샷을 읽습니다.
2. `store.subscribe(listener)`로 구독합니다.
3. 최신 스냅샷을 프레임워크 런타임 안으로 옮깁니다.
4. 쓰기는 `store.setState(next)`나 action helper를 통해 전달합니다.
5. 소유 범위가 끝날 때 반환된 unsubscribe 함수를 호출해 정리합니다.

바닐라 스토어를 source of truth로 유지하세요. 어댑터는 스냅샷을 프레임워크 모델로 번역하고 쓰기는 공개 store API로 다시 보냅니다.

## React

React는 외부 스토어를 위한 내장 브리지인 `useSyncExternalStore`를 제공합니다. React가 구독 정리를 제어하고 렌더 중 일관된 스냅샷을 읽도록 이 API를 사용하세요.

```tsx lineNumbers
import { useSyncExternalStore } from "react";
import { Store } from "@ilokesto/store";

type CounterState = {
  count: number;
};

export const counterStore = new Store<CounterState>({ count: 0 });

export function useCounterStore() {
  return useSyncExternalStore(
    counterStore.subscribe.bind(counterStore),
    () => counterStore.getState(),
    () => counterStore.getInitialState(),
  );
}

export function incrementCounter() {
  counterStore.setState((state) => ({ count: state.count + 1 }));
}

export function CounterButton() {
  const state = useCounterStore();

  return <button onClick={incrementCounter}>Count: {state.count}</button>;
}
```

이 hook은 selector나 batching을 추가하지 않습니다. `subscribe`와 `getState`를 React의 외부 스토어 계약에 연결할 뿐입니다. `getInitialState()`는 SSR과 hydration에 안정적이고 결정적인 서버 스냅샷을 제공합니다.

## Vue

Vue에서는 스토어 스냅샷을 `shallowRef`로 옮기고 `onUnmounted`로 생명주기 정리를 등록합니다.

```ts lineNumbers
import { onUnmounted, shallowRef } from "vue";
import { Store } from "@ilokesto/store";

type CounterState = {
  count: number;
};

export const counterStore = new Store<CounterState>({ count: 0 });

export function useCounterStore() {
  const state = shallowRef(counterStore.getState());

  const unsubscribe = counterStore.subscribe(() => {
    state.value = counterStore.getState();
  });

  onUnmounted(unsubscribe);

  function increment() {
    counterStore.setState((current) => ({ count: current.count + 1 }));
  }

  return { state, increment };
}
```

스토어가 전체 스냅샷을 교체하는 방식이라면 `shallowRef`를 사용하세요. `state.value`를 직접 변경하지 마세요. `Readonly<T>`는 TypeScript 수준의 신호일 뿐이고, 코어 스토어는 런타임에서 값을 동결하지 않습니다.

## Svelte

Svelte의 store contract도 구독 기반입니다. 작은 어댑터는 스냅샷용 readable store와 쓰기용 별도 action helper를 노출할 수 있습니다.

```ts lineNumbers
import { readable } from "svelte/store";
import { Store } from "@ilokesto/store";

type CounterState = {
  count: number;
};

export const counterStore = new Store<CounterState>({ count: 0 });

export const counter = readable(counterStore.getState(), (set) => {
  set(counterStore.getState());

  const unsubscribe = counterStore.subscribe(() => {
    set(counterStore.getState());
  });

  return unsubscribe;
});

export function incrementCounter() {
  counterStore.setState((state) => ({ count: state.count + 1 }));
}
```

readable setup 함수에서 `unsubscribe`를 반환하면 마지막 구독자가 떠날 때 Svelte가 필요한 정리 함수를 받을 수 있습니다.

## Angular

Angular는 스토어를 service 소유 signal로 연결할 수 있습니다. service가 구독을 소유하고 컴포넌트용 read model을 노출하며, 그 service를 만든 범위를 위한 명시적인 정리 메서드를 제공합니다.

```ts lineNumbers
import { Injectable, OnDestroy, signal } from "@angular/core";
import { Store } from "@ilokesto/store";

type CounterState = {
  count: number;
};

@Injectable()
export class CounterStoreService implements OnDestroy {
  private readonly store = new Store<CounterState>({ count: 0 });
  readonly state = signal(this.store.getState());

  private readonly unsubscribe = this.store.subscribe(() => {
    this.state.set(this.store.getState());
  });

  increment() {
    this.store.setState((state) => ({ count: state.count + 1 }));
  }

  ngOnDestroy() {
    this.unsubscribe();
  }
}
```

해당 범위에 묶인 정리가 필요하다면 service를 컴포넌트나 feature 범위에서 제공하세요. 애플리케이션 루트에서 제공한다면 보통 구독은 앱 생명주기 동안 유지됩니다.

## 모든 어댑터의 주의점

- **스냅샷 일관성**: 프레임워크의 구독 모델 안에서 `getState()`로 스냅샷을 읽으세요. React는 `useSyncExternalStore`를 사용해야 합니다.
- **정리**: unsubscribe 함수를 호출하거나, teardown을 소유하는 프레임워크 API에 반환하세요.
- **변경 회피**: 스냅샷을 불변 값으로 다루세요. `Readonly<T>`는 런타임에서 상태를 동결하거나 복제하지 않습니다.
- **스케줄러 가정 없음**: Store 알림은 동기식입니다. 이 패키지는 batching, async scheduling, render coordination을 추가하지 않습니다.
- **어댑터 범위**: 이 예제는 어댑터 패턴이지 공식 프레임워크 패키지가 아닙니다. selector와 action은 raw store bridge 위에 두세요.
