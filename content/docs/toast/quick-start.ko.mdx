# 빠른 시작

이 페이지는 최소한의 맥락으로 동작하는 toast stack 하나를 화면에 올리는 데 집중합니다.

정말 짧게 끝내고 싶다면 두 단계만 기억하면 됩니다. `<Toaster />`를 마운트하고, 그다음 `toast.success(...)`를 호출하면 됩니다. 나머지 API는 모두 그 runtime 등록 위에 쌓입니다.

```package-install
@ilokesto/toast
```

## 1. `Toaster` 마운트하기

`toast.*` 호출은 runtime이 등록되어 있어야만 동작합니다. 실제로는 `<Toaster />`를 마운트해야 한다는 뜻입니다.

```tsx
import { Toaster } from '@ilokesto/toast';

function App() {
  return <Toaster />;
}
```

앱 셸의 상단에 두는 편이 가장 자연스럽습니다. 이 패키지는 숨겨진 전역 runtime을 만들어주지 않기 때문에, 이 마운트 지점이 곧 facade가 실제로 동작하기 시작하는 순간입니다.

## 2. facade 호출하기

```tsx
import { toast } from '@ilokesto/toast';

toast.success('저장되었습니다');
```

이것만으로도 기본 runtime에 토스트가 표시됩니다.

`react-hot-toast`에서 넘어오는 경우 이 구간은 의도적으로 익숙하게 느껴집니다. 차이는 그 다음부터입니다. 이 패키지에서는 runtime이 암묵적 전역이 아니라 provider-scoped라는 점을 기억하면 됩니다.

## 3. 다른 내장 variant도 사용하기

```tsx
toast('Hello');
toast.error('문제가 발생했습니다');
toast.loading('저장 중...');
```

`toast.loading()`은 다른 동작이 갱신하거나 dismiss할 때까지 무한 duration을 사용합니다.

아직 끝나지 않은 작업을 솔직하게 보여줘야 하는 상황에서는 이 형태가 특히 잘 맞습니다.

## 4. promise toast도 익숙한 경로에 가깝다

```tsx
toast.promise(fetch('/api/save'), {
  loading: '저장 중…',
  success: '저장 완료',
  error: '실패',
});
```

loading -> success/error 전환에서 같은 toast id가 재사용됩니다.

이 재사용은 중요합니다. 사용자는 여러 개의 토스트를 연달아 보는 것이 아니라, 하나의 알림이 상태를 바꾸는 것으로 느끼게 됩니다.

## 처음에는 이 구성이 가장 좋다

대부분의 앱은 아래 정도에서 시작하는 것이 좋습니다.

```tsx
import { Toaster } from '@ilokesto/toast';

export function AppShell() {
  return (
    <>
      {/* 앱 라우트 / 레이아웃 */}
      <Toaster position="top-right" />
    </>
  );
}
```

한동안은 여기서 멈춰도 충분합니다. `toasterId`, headless rendering, custom row는 정말로 단일 전역 알림 표면을 넘어서는 요구가 생길 때 꺼내면 됩니다.
