# @ilokesto/toast

`@ilokesto/toast` is a React toast package built around a provider-scoped runtime and a familiar `toast.*` facade. Internally it uses `@ilokesto/overlay` only for presence lifecycle, while toast policy and rendering stay inside this package.

It is designed for the path most teams actually care about: mount a toaster once, call `toast.*` from application code, keep the default renderer polished, and only drop lower when your product really needs custom rows or multiple runtimes.

The package feels close to `react-hot-toast` on the common path, but it is more explicit about runtime ownership and gives you a top-layer transport option when you want overlay behavior that is not tied to the normal DOM stacking context.

## Why teams reach for it

- **Fast common path**: `toast()`, `toast.success()`, `toast.error()`, `toast.loading()`, `toast.custom()`, and `toast.promise()` are all there.
- **Runtime ownership is explicit**: each `Toaster` owns one runtime, and `toasterId` gives you deliberate separation instead of accidental global coupling.
- **Polished default renderer**: the stock row renderer already includes status icons, loading states, motion, and sensible defaults.
- **Headless escape hatch**: if the stock UI stops being enough, `useToaster()` and `ToastBar` let you keep the state model and replace the presentation.
- **Extra transport mode**: `transport="top-layer"` gives you a rendering option that `react-hot-toast` does not expose.

## What it intentionally does not give you

- No global singleton that works without a mounted `Toaster`
- No notification center or inbox model
- No attempt to hide that a runtime registry exists behind the facade

Those boundaries matter. They keep the package focused on transient notifications instead of quietly growing into a broader message center abstraction.

## Quick look

```tsx
import { Toaster, toast } from '@ilokesto/toast';

function App() {
  return (
    <>
      <button onClick={() => toast.success('Saved successfully')}>Show toast</button>
      <Toaster />
    </>
  );
}
```

That is enough to get the default stack on screen. The rest of the package is about controlling where that runtime lives, how rows render, and how much of the stack you want to own yourself.
