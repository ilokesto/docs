# @ilokesto/toast

`@ilokesto/toast`는 provider-scoped runtime과 익숙한 `toast.*` facade 위에 세운 React toast 패키지입니다. 내부적으로는 `@ilokesto/overlay`를 presence lifecycle 용도로만 사용하고, toast 정책과 렌더링은 이 패키지 안에서 처리합니다.

이 패키지는 실제 제품 코드에서 가장 자주 쓰는 경로를 매끄럽게 만드는 데 집중합니다. `Toaster`를 한 번 마운트하고, 애플리케이션 코드에서 `toast.*`를 호출하고, 기본 렌더러는 충분히 polished하게 유지하되, 정말 필요할 때만 lower-level API로 내려가도록 구성했습니다.

일반적인 사용감은 `react-hot-toast`에 가깝지만, runtime의 소유권을 더 명시적으로 드러내고, 일반 DOM stacking context를 넘고 싶을 때 `top-layer` transport까지 선택할 수 있다는 점이 다릅니다.

## 왜 이 패키지를 쓰게 되는가

- **빠른 공통 경로**: `toast()`, `toast.success()`, `toast.error()`, `toast.loading()`, `toast.custom()`, `toast.promise()`가 익숙하게 준비되어 있습니다.
- **runtime 소유권이 명확함**: 각 `Toaster`가 하나의 runtime을 소유하고, `toasterId`로 분리합니다.
- **기본 렌더러 완성도**: 상태 아이콘, loading 상태, motion, 기본 옵션이 이미 포함되어 있습니다.
- **headless 확장 가능성**: 기본 UI가 부족해지는 시점에는 `useToaster()`와 `ToastBar`로 상태 모델은 유지하고 표현만 바꿀 수 있습니다.
- **추가 transport 옵션**: `transport="top-layer"`는 `react-hot-toast`에 없는 렌더링 선택지입니다.

## 의도적으로 제공하지 않는 것

- mounted `Toaster` 없이 동작하는 전역 싱글턴
- notification center나 inbox 모델
- facade 뒤에 runtime registry가 있다는 사실을 완전히 감추는 추상화

이 경계는 의도적입니다. 이 패키지가 일시적인 알림에 집중한 채로 커지게 해주고, 조용히 더 큰 메시지 센터 추상화로 번지는 것을 막아줍니다.

## 훑어보기

```tsx
import { Toaster, toast } from '@ilokesto/toast';

function App() {
  return (
    <>
      <button onClick={() => toast.success('저장되었습니다')}>토스트 표시</button>
      <Toaster />
    </>
  );
}
```

이 코드만으로도 기본 스택을 올릴 수 있습니다. 이후 문서는 runtime을 어디에 둘지, row 렌더링을 어디까지 제어할지, 어느 시점에 headless API로 내려갈지를 설명합니다.
