# 접근자

접근자는 `create`가 반환한 adapter에 붙어 있는 정적 메서드입니다. 액션 파일, 리스너, 그 밖의 명령형 코드에서 상태를 갱신해야 한다면 `writeOnly()`부터 사용하세요. 렌더링과 무관한 코드가 동기 snapshot을 읽어야 한다면 `readOnly()`를 사용하세요.

## `writeOnly()`

`writeOnly()`는 표준적인 명령형 작성자(imperative writer)입니다. 이는 스토어의 `setState` 함수(또는 리듀서를 사용하는 경우 `dispatch`)를 반환합니다.

- **framework lifecycle 외부**: 액션, side effect, 이벤트 리스너를 정의할 때 권장되는 방법입니다.
- **컴포넌트 내부**: 컴포넌트가 상태를 구독하고 selector 변경에 따라 다시 렌더링되어야 한다면 adapter를 직접 사용하세요.

`writeOnly()`를 호출할 때마다 bound writer 함수가 새로 만들어지지만, 중요한 안정성은 참조 자체보다 같은 store를 계속 가리킨다는 점에 있습니다.

```ts lineNumbers
const useCounter = create({ count: 0 });

// 독립적인 액션 파일을 정의할 때 이상적입니다.
export const increment = () => {
  const setState = useCounter.writeOnly();
  setState(state => ({ count: state.count + 1 }));
};
```

이 방식은 액션 모듈을 작고 직접적으로 유지합니다. adapter를 가져오고, `writeOnly()`를 호출한 뒤, 반환된 함수로 상태를 씁니다.

## `readOnly()`

`readOnly()`는 현재 store snapshot을 반환하고, 필요하면 selector로 투영합니다. 동기 읽기 helper이며 호출자를 future update에 구독시키지 않습니다.

```tsx lineNumbers
export function getCurrentCount() {
  return useCounter.readOnly((state) => state.count);
}
```

값이 렌더링 결과에 영향을 준다면, 컴포넌트가 정상적으로 구독하고 갱신될 수 있도록 selector와 함께 framework adapter를 직접 쓰는 편이 좋습니다.

## 대신 vanilla `Store`를 써야 하는 경우

non-framework 코드가 이미 store를 직접 소유한다면, `@ilokesto/store`의 vanilla `Store` API가 가장 명확한 명령형 경계입니다.

가장 좋은 패턴은 스토어를 별도로 생성하고 이를 `create()`에 전달하는 것입니다:

```ts lineNumbers
import { Store } from '@ilokesto/store';
import { create } from '@ilokesto/state/react';

// 1. vanilla store를 먼저 생성합니다.
export const counterStore = new Store({ count: 0 });

// 2. 이 스토어로부터 훅을 생성합니다.
export const useCounter = create(counterStore);

// 3. 소유한 vanilla store를 직접 읽을 수도 있습니다.
export const checkCount = () => {
  console.log(counterStore.getState().count);
};
```

## 액션 파일 패턴

스토어와 액션을 분리해서 관리하는 것은 흔한 아키텍처 패턴입니다. 접근자를 쓰면 코드가 깔끔해집니다:

```ts lineNumbers
// stores/auth.ts
export const useAuth = create({ user: null, loading: false });

// actions/auth.ts
import { useAuth } from '../stores/auth';

export const login = async (credentials) => {
  const setState = useAuth.writeOnly();
  setState((prev) => ({ ...prev, loading: true }));
  const user = await api.login(credentials);
  setState((prev) => ({ ...prev, user, loading: false }));
};
```

이 패턴은 쓰기에 집중해서 사용하세요. 액션 파일이 현재 상태도 확인해야 한다면 빠른 snapshot에는 `readOnly()`를 쓰고, 소유권을 adapter 밖에 유지해야 한다면 vanilla `Store`를 별도로 정의해 `store.getState()`로 읽으세요.

## 흔히 하는 실수

1. **`readOnly()`가 구독한다고 기대하기**: snapshot을 반환할 뿐, store 변경 시 컴포넌트를 갱신하지 않습니다.
2. **adapter 반환 형태 무시**: React는 tuple, Vue/Solid/Angular는 객체, Svelte는 store-like 객체를 반환합니다.
3. **컴포넌트 안에서 `readOnly()` 남용**: 렌더링에 값이 필요하다면 selector와 함께 adapter를 직접 사용하세요.
