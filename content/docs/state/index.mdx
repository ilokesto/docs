# @ilokesto/state

`@ilokesto/state` turns external store state into React hooks: the store stays outside React, while reads and subscriptions flow through `useSyncExternalStore`.

## What this package gives you

- **One `create()` entry point** for state objects or vanilla stores.
- **Plain state and reducer modes** for different update styles.
- **Selector subscriptions** that keep component reads narrow.
- **Imperative accessors** such as `writeOnly()` for work outside components.
- **Store middleware** for logging, persistence, validation, and debugging.

## What it intentionally does not give you

- No provider-first app structure.
- No Zustand-style initializer.
- No custom equality API for selectors.
- No hidden store behind the hook.

## Installation

```package-install
@ilokesto/state
```

## Quick Look

```tsx lineNumbers
import { create } from '@ilokesto/state';

const useCounter = create({ count: 0 });

function Counter() {
  const [count, setState] = useCounter((state) => state.count);

  return (
    <button onClick={() => setState((prev) => ({ ...prev, count: prev.count + 1 }))}>
      {count}
    </button>
  );
}
```

The shape is small:

- `create()` builds a hook from external state,
- the selector decides what the component reads,
- the writer still updates the full store state.
