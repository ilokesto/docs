# `create`

`create`는 `@ilokesto/state`의 핵심 진입점입니다. 상태를 정의하고, 컴포넌트가 그 상태를 읽고 갱신할 때 호출하는 훅을 반환합니다.

`create`는 각 framework adapter subpath에 존재합니다. 사용하는 프레임워크에 맞춰 `@ilokesto/state/react`, `@ilokesto/state/vue`, `@ilokesto/state/angular`, `@ilokesto/state/svelte`, `@ilokesto/state/solid`에서 가져오세요.

오버로드는 adapter 사이에서 공유되지만 반환 형태는 프레임워크마다 다릅니다. React는 hook tuple, Vue는 composable result, Angular는 signal, Svelte는 store 객체, Solid는 accessor를 반환합니다.

## create 모양 고르기

| 상황 | 사용하기 |
|---|---|
| framework adapter가 작은 공유 상태 값을 소유한다 | `create(initialState)` |
| vanilla `Store`가 이미 상태를 소유한다 | `create(store)` |
| 업데이트를 action으로 표현하고 싶다 | `create(reducer, initialState)` |
| 서버 데이터가 한 렌더/요청의 시작점이다 | `create(initialState)`를 호출하는 factory |

반환되는 값은 항상 import한 adapter에 속합니다. 정확한 반환 형태는 [프레임워크 어댑터](./adapters)에서 시작하세요.

## 호출 시그니처

`create` 함수는 두 가지 주요 운영 모드를 지원하도록 오버로드되어 있습니다.

### 상태 모드

상태 모드에서는 초기 상태를 직접 제공합니다. 반환된 훅은 React의 `useState`와 유사한 `setState` 함수를 제공합니다.

```ts lineNumbers
import { create } from '@ilokesto/state/react';

// 1. 초기 상태 값을 사용
const useCounter = create({ count: 0 });

// 2. 기존 Store 인스턴스를 사용
import { Store } from '@ilokesto/store';
const store = new Store({ count: 0 });
const useCounterFromStore = create(store);
```

두 번째 형태가 실제 사용 사례라면 기존 스토어 사용이 다음 주제로 더 잘 맞습니다. 여기서는 `create(store)`가 어떤 경계에 어울리는지, 그리고 기존 스토어를 React에 연결해도 무엇은 바뀌지 않는지를 설명합니다.

### 리듀서 모드

리듀서 모드에서는 리듀서 함수와 초기 상태(또는 스토어)를 제공합니다. 반환된 훅은 `dispatch` 함수를 제공합니다.

```ts lineNumbers
type State = { count: number };
type Action = { type: 'increment' } | { type: 'decrement' };

const reducer = (state: State, action: Action): State => {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'decrement': return { count: state.count - 1 };
    default: return state;
  }
};

const useCounter = create(reducer, { count: 0 });
```

## 어댑터 동작 방식

`create`가 반환한 adapter는 셀렉터 함수를 받고, 선택된 값과 현재 모드에 맞는 writer를 함께 반환합니다. 컨테이너의 모양은 프레임워크마다 다릅니다.

```tsx lineNumbers
function Counter() {
  // [선택된상태, 업데이트함수]를 반환합니다.
  const [count, setCountOrDispatch] = useCounter(state => state.count);
  // ...
}
```

- **상태 모드**: 두 번째 요소는 스토어 writer입니다. 셀렉터가 한 필드만 반환하더라도 writer는 전체 다음 상태 또는 전체 상태를 만드는 updater를 받습니다: `setState((prev) => ({ ...prev, count: prev.count + 1 }))`.
- **리듀서 모드**: 두 번째 요소는 액션을 받는 `dispatch` 함수입니다: `dispatch({ type: 'increment' })`.

위 React 예시는 tuple 형태를 보여줍니다. Vue, Angular, Svelte, Solid는 같은 selected state와 writer를 각 프레임워크의 native primitive로 노출합니다.

## 동작 참고 사항

`create`는 `(set, get) => ({ ... })` 같은 Zustand 스타일 초기화 함수를 지원하지 **않습니다**. 위에 나온 초기 상태 값, 기존 `Store`, 또는 리듀서 쌍을 전달하세요.

각 adapter는 프레임워크의 lifecycle model을 통해 구독합니다. 셀렉터는 같은 외부 스토어 계약에서 값을 읽고, 노출되는 값만 프레임워크 native 형태를 따릅니다. SSR에서는 서버 스냅샷에 `store.getInitialState()`를 사용합니다.
